Subject: 21181 * 2^1148 + 1 (350 digits): ECM status and SNFS plan

Hello everyone,

I have been working on the Proth number 21181 * 2^1148 + 1 (350 digits,
composite, no known factors in factordb), and I would like to report my ECM
effort so far and reserve the number for further ECM and an eventual SNFS.

(k = 21181 is one of the remaining Sierpinski candidates, but this n is
already known to be composite, so factoring it has no bearing on the
Sierpinski problem. It is simply a factoring target I picked.)

I also compared other degrees (all with optimized skew). Since 1148 = 7*164,
the degree-7 polynomial 21181*x^7+1 (m = 2^164) is also available, and it
scores higher with the small CADO-NFS defaults. At bounds suitable for a job

so f(2^191) = 21181 * 2^1148 + 1 exactly.

Current status:

- ECM with GMP-ECM 7.0.5 (default B2), no factor found so far:
    B1=11e6: 160 curves
    B1=43e6: <N> curves (of 17769 for t50)
- CADO-NFS test sieving: about 1 million relations (q starting around
  40000000). The estimated requirement is around 4.4 billion relations.

I am aware that this is far from the usual ECM depth before an SNFS (the rule
of thumb of about 2/9 of the SNFS difficulty would mean around t75), and that
an SNFS of this difficulty is at NFS@Home scale rather than something my
single machine (8 physical cores) can sieve. So the SNFS is a long-term plan,
and for now I would like to ask:

1. Has anyone already run ECM on this number? factordb has no way to record
   ECM effort, so any unreported curves would help avoid duplicated work.
2. If anyone would like to contribute ECM curves, please post the B1 values
   and curve counts here, and I will keep a running total.

I will report here if a factor turns up.

Thank you!
